# j2ee-fitness-nutrition-ecommerce

## Project Overview

University final project for a J2EE Application Development course. An e-commerce website specializing in fitness and nutrition supplements (Whey Protein, Mass Gainer, Pre-workout, Vitamins). The system supports product variants (flavor, weight with different prices and stock), session-based shopping cart, user authentication with role-based access, and a full admin panel.

## Tech Stack & Architecture Rules

### STRICT RULES
- **Architecture**: Monolithic MVC with Server-Side Rendering. DO NOT use or suggest React, Vue, Angular, NextJS, or any SPA framework.
- **Views**: Thymeleaf templates ONLY. All pages are rendered server-side. DO NOT create REST APIs returning JSON unless specifically asked.
- **Controllers**: Return view names (String), NOT `ResponseEntity` or `@ResponseBody`. Use `@Controller`, NOT `@RestController` (except for AJAX cart operations if needed).
- **Security**: Session-based authentication. NO JWT tokens. CSRF enabled (Thymeleaf handles automatically with `th:action`).

### Package Structure
```
com.example.j2ee_fitness_nutrition_ecommerce
├── config/          # SecurityConfig, WebConfig
├── controller/      # @Controller classes (public + admin)
├── dto/             # Request/Response DTOs, form objects
├── entity/          # JPA @Entity classes
├── enums/           # Role, OrderStatus
├── repository/      # Spring Data JPA repositories
├── service/         # Business logic interfaces
├── service/impl/    # Service implementations
└── util/            # Helper/utility classes
```

### Naming Conventions
- Entities: singular (Product, User, Order)
- Tables: auto-generated by JPA (use `@Table(name="...")` if custom needed)
- Controllers: `{Feature}Controller` (e.g., ProductController, AdminProductController)
- Services: `{Entity}Service` interface + `{Entity}ServiceImpl`
- Repositories: `{Entity}Repository`
- Templates: `src/main/resources/templates/{feature}/{action}.html`

## Database Schema Outline

### Entities & Relationships

```
User (id, fullName, email, password, phone, address, role, enabled, createdAt)
  └── 1:N → Order

Category (id, name, slug, description, imageUrl, active)
  └── 1:N → Product

Product (id, name, slug, description, imageUrl, brand, active, createdAt)
  ├── N:1 → Category
  └── 1:N → ProductVariant

ProductVariant (id, flavor, weight, price, stock, sku, active)
  └── N:1 → Product

Order (id, orderCode, status, totalAmount, fullName, phone, address, note, createdAt)
  ├── N:1 → User
  └── 1:N → OrderDetail

OrderDetail (id, quantity, unitPrice, subtotal)
  ├── N:1 → Order
  └── N:1 → ProductVariant
```

### Enums
- **Role**: `ADMIN`, `USER`
- **OrderStatus**: `PENDING`, `CONFIRMED`, `SHIPPING`, `DELIVERED`, `CANCELLED`
